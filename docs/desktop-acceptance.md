# 桌面嵌入验收

## 当前实测证据

环境：Windows build 26200 / x64，桌面 DPI 120（125%），.NET SDK 10.0.401。

- Release 编译成功。
- 原型已在真实用户桌面运行。
- 创建的 HWND 的直接父窗口类为 `SHELLDLL_DefView`，不是顶层悬浮窗。
- 原型初次区域为 `[2261,80,2536,480]`，像素尺寸 275×400，与 220×320 DIP 的 125% 缩放一致。
- 卡片中心在被工作窗口覆盖时命中 Chrome 窗口，符合被普通窗口遮挡的预期；这不等同于完整视觉验收。
- 验收窗口已通过可访问性树与截图检查。

用户在 2026-09-11 回复“已测试，成功”，确认本轮请求的显示、点击、拖动测试成功。其他未明确执行的场景继续保留待测状态。

## 实机验收

| 场景 | 操作 | 通过标准 | 当前结果 |
|---|---|---|---|
| 显示桌面 | 用户按 Win+D | 卡片留在桌面可见，再恢复工作窗口可被遮挡 | 用户确认成功 |
| 点击 | 点击“测试桌面交互” | 次数增加，验收日志记录一次 | 用户确认成功；日志有点击证据 |
| 拖动与锁定 | 拖动标题，然后锁定再拖动 | 未锁定可移动，锁定后不移动 | 拖动由用户确认；锁定待单独验证 |
| 桌面其他区域 | 在卡片外选中图标、框选和打开菜单 | 与未运行原型时一致 | 待验证 |
| 位置记忆 | 退出原型再打开 | 保留位置和锁定状态 | 待验证 |
| Explorer 恢复 | 用户在方便时重启 Windows 资源管理器 | 卡片自动重新嵌入，交互有效，日志记录重建 | 待验证 |
| 锁屏恢复 | 用户锁定并解锁系统 | 卡片显示与交互正常 | 待验证 |
| DPI | 用户切换缩放比例 | 卡片尺寸与文字清晰，无错位或重复窗口 | 待验证 |
| 显示器 | 用户拔插外接显示器（如有） | 卡片回到有效工作区域，可点击拖动 | 待验证 |

不会自动重启用户正在使用的 Explorer、锁定桌面或调整显示设置。请在方便时执行这些实机步骤。没有硬件条件的场景标记“未验证”，不得填“通过”。

## 门槛

收到用户对原型成功的确认后，继续实现完整应用。若出现嵌入异常，先修复并重测；无法稳定实现则回到产品讨论，不改成悬浮窗冒充通过。

音频功能现已接入；完整功能与性能测试结果记录在 `validation.md`，每项以实际测试状态为准。
