# 0.3.4：输出缓冲区残留修复

## 原因与改动

本机复现总音量高时持续嗡嗡声。NAudio 的 SampleToWaveProvider 使用 WaveBuffer 将同一字节数组暴露为浮点缓冲区。旧 MixBus 对该缓冲调用 Array.Clear；该方法按实际数组的字节元素计数，只清除请求音频范围的四分之一。随后混音以 += 写入，未清除的旧音频参与下一轮混音，总增益高时形成明显残留。

改为浮点 Span 清零，同时修复 LoopSample 静音尾部和 FloatRing 缓冲不足路径的同类写法。诊断采样改用浮点 Span.CopyTo，避免 Array.Copy 按底层字节数组执行数值转换。

无需改设备、均衡器或系统音量。音量映射、峰值保护和原有用户数据格式不变。

## 验证

- 修复前，真实 SampleToWaveProvider 连续复用100个缓冲区，与直接混音最大样本差 **0.4758505**，回归测试失败。
- 修复后，相同测试通过（阈值 0.000001）。另验证声音移除及缓冲耗尽后输出全零、实际输出适配器下采样逐样本一致。
- 信号测试 **8项通过**；普通浮点缓冲下总音量100%的1kHz THD+N为0.000004%。该数值只说明对应数字路径，不等于扬声器实测。
- 基础验证 **29项通过**，包含18种声音、循环边界、四路混音、有界缓冲与按需释放。
- 用户修复版试听：2026-09-12，使用同一电台、总音量100%与媒体约20%，明确反馈“消失了”。确认本机报告的嗡嗡声消失；不扩大为所有设备均已验证。没有进行新性能长测。

先前诊断的 settings.json 状态有效；旧版 software-output.wav 受上述 Array.Copy 转换问题影响，不能作为频谱或响度证据。先前 A/B 记录还显示炉火与窗边雨启用，已向用户说明；输出缓冲残留已通过独立回归测试复现，不依赖这两路环境声。

## 可选诊断

仅使用 --audio-diagnostic-dir <目录> 启动时，音量或声道状态稳定后采集五秒自身最终 PCM，记录界面值与混音器状态，最多十二段。普通启动不自动采样；不读取麦克风、系统回环或其他应用声音，也不上传。采样位于混音及峰值保护之后、WASAPI之前。

诊断记录位于 artifacts，排除在源码提交与源码包之外。
