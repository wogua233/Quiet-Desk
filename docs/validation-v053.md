# 静隅 0.5.3 来源状态与重新检查

2026-09-14，Windows 本机，Release / win-x64 自包含发布。

## 原因

来源状态持久化，只有应用自身请求完成才更新。独立命令行测试成功不更新运行实例的数据。未勾选来源不会自动请求；此前手动“刷新并翻译总结”也复用自动来源退避条件，导致用户点击刷新仍跳过失败来源，并笼统显示“订阅检查完成”。

## 修改

- 订阅页增加每个刊物的“重新检查”，支持未订阅来源，不改变订阅选择、不调用 AI。
- 订阅页整体按钮改为“仅刷新订阅”；文章页的刷新仍保留翻译总结语义。
- 手动刷新绕过来源失败等待期，自动刷新保留退避并按最近来源重试时间调度。
- 显示正在检查、未订阅不自动检查、最近一次失败、自动重试时间；汇总成功、失败和等待重试数量。
- 成功或 HTTP 304 替换失败状态；勾选操作合并到最新来源记录，不把陈旧状态写回。
- 单刊检查期间防止重复请求，完成后恢复按钮。仍使用原有有界响应和两路来源并发限制。

## 验证

发布成功，83 项 PASS，退出码 0，见 [检查记录](validation-v053-checks.txt)。新增模拟来源测试覆盖失败与退避、自动跳过说明、手动绕过并恢复、陈旧勾选不覆盖检查结果、未订阅来源检查、304、检查中状态、重复点击合并、不创建 AI 队列。

本轮未调用真实收费 AI，未刷新用户实际订阅数据库，未替换正在运行的 0.5.2 实例；没有把模拟测试当成实际界面操作或实时出版社连接通过。新增按钮的实机交互及特殊 DPI 尚待试用；本轮未重新长测音乐。
